# equity-lit-auditor in PRSGuard

How the teammate's ClawBio skill `equity-lit-auditor` (Genome Equity hackathon) is integrated into PRSGuard,
how it was validated against the live APIs, what was fixed, and the rules that keep it honest.

Date of this work: 2026-09-26. ClawBio pin: `0ba950565ee6a0fe9da3bde2164f6c814bd57dc9`.

## TL;DR

```bash
scripts/setup.sh                                   # venv, pinned vendor/ClawBio, registration, offline smoke test
cd vendor/ClawBio
../../.venv/bin/python clawbio.py run equity-lit --demo --output /tmp/eq_demo          # SYNTHETIC, offline
../../.venv/bin/python clawbio.py run equity-lit --pgs-trait "type 2 diabetes" --output /tmp/eq_t2d
../../.venv/bin/python clawbio.py run prs-gate --demo --output /tmp/gate_demo
```

- The skill lives in `skills/equity-lit-auditor/` (this repo is its home). `scripts/install_into_clawbio.py`
  links it, and `skills/prs-applicability-gate/`, into a ClawBio checkout and registers
  `clawbio.py run equity-lit` and `clawbio.py run prs-gate`.
- Its 0-100 literature equity score is **context only**. It never feeds an applicability decision.
- Synthetic demo output is labelled `SYNTHETIC DEMO` in every artifact and flagged in every machine-readable
  output. Live mode never falls back to demo data.

### How registration works in ClawBio at the pin

- **CLI alias**: the static `SKILLS` dict in `clawbio/cli.py`. Each entry names the script, demo args and a
  flag allowlist (`allowed_extra_flags`, `allowed_extra_flags_without_values`, `extra_path_flags`);
  flags not on the list are dropped silently by the runner (SEC INT-001). Descriptor skills
  (`INTENTS.json`) exist too, but they are given an empty flag allowlist by design, so `--pgs-trait` could
  not reach the skill that way.
- **Catalogue**: `scripts/generate_catalog.py` reads SKILL.md frontmatter and the `SKILLS` dict (by AST) and
  writes `skills/catalog.json`: `cli_alias`, `demo_command`, `maturity_tier`, trigger keywords.
- **Public counts**: README, llms.txt, CITATION.cff, .zenodo.json and the plugin manifests repeat
  catalogue counts; `tests/test_public_claims.py` fails on drift.
- **Data handling**: every skill with outbound calls needs a row in `docs/data-handling.md`.
- **Runner quirks that matter here**: the runner itself defines `--query` (BigQuery) and `--max-results`
  (Bioconductor) and re-forwards them, so both still reach this skill (verified). It starts the skill with
  `cwd` = the skill folder, so `--cache-dir` is registered as a path flag and resolved against the caller's
  working directory.

## 2. How the integration is done now

`scripts/install_into_clawbio.py [--clawbio PATH] [--copy] [--force] [--check] [--strict]`

1. Symlinks (default) or copies (`--copy`, with a `.prsguard-installed` marker) `skills/equity-lit-auditor`
   and `skills/prs-applicability-gate` into `<clawbio>/skills/`. Symlinks are relative when the checkout
   is inside this repo (`vendor/ClawBio`), absolute otherwise. A same-named folder that the script did not
   install is never replaced without `--force` (ClawBio may one day ship its own).
2. Registers `equity-lit` and `prs-gate` in `SKILLS`, between
   `# >>> prsguard-managed skills` / `# <<< prsguard-managed skills` markers; re-runs replace the block. An
   alias that upstream already defines is left alone.
3. Runs ClawBio's `scripts/generate_catalog.py`.
4. Re-derives the public counts from the new catalogue.
5. Writes the `equity-lit-auditor` row in `docs/data-handling.md`.
6. Verifies by importing `clawbio.cli` and reading the catalogue. A skill whose source folder lacks `SKILL.md`
   or its script is reported as *pending* (exit 0, or 1 with `--strict`); in the final repository both skills are
   complete and nothing is pending.

Idempotency was checked by hashing `git diff` before and after a second run (identical), on
`vendor/ClawBio` and on a fresh `--no-local` clone at the pin, in copy mode, symlink mode and when switching
between them. The fresh-clone result equals the vendor result for every tracked file.

`prs-gate` is registered with only `--input`, `--output` and `--demo` (the runner's own flags). **Its
`--config` flag is deliberately not forwarded.** `clawbio.py run` is the interface an LLM agent uses, and the
project's boundary is that orchestration may not change thresholds; the ClawBio runner drops unregistered flags,
so a run through ClawBio always uses the shipped `config/calibration.yaml`. Alternative calibrations are for
calibration research through the gate's own CLI, and such results carry `config_canonical: false` and a
NON-CANONICAL CALIBRATION banner. `tests/test_clawbio_registration.py` checks both the registration and that
`clawbio.py run prs-gate --config <anything>` still reports the shipped config's SHA-256.

**After editing either skill's SKILL.md, re-run the installer**: the catalogue copies the frontmatter, and
ClawBio's `test_checked_in_catalog_is_current` fails until it is regenerated.

`scripts/setup.sh` wraps all of it: `.venv` via uv with the exact versions in `uv.lock` (`uv sync --frozen`;
without uv, `python3 -m venv` + `pip install -e ".[reference,dev]"`, unlocked),
clone + pin `vendor/ClawBio` (refuses to move a checkout that has local changes), makes sure the runner
can import (it only needs opentelemetry-sdk and PyYAML, both already PRSGuard dependencies; ClawBio's full
dependency set, with BigQuery and OpenAI, is not installed), runs the installer, then an offline
`clawbio.py run equity-lit --demo` smoke test that also asserts the `SYNTHETIC DEMO` flag. Extra arguments
go to the installer (`scripts/setup.sh --copy`).

### Relocation fix in the skill

`equity_lit_auditor.py` used `Path(__file__).resolve().parent.parent` as the ClawBio root. Symlinked into
ClawBio, `resolve()` points back into PRSGuard, so `clawbio.common` was not importable: `result.json` lost
the ClawBio envelope, no `reproducibility/` bundle was written, and two tests failed
(`test_every_documented_file_exists`, `test_runner_forwards_value_less_flags`). It now looks for a checkout
in `$CLAWBIO_DIR`, the unresolved (symlink) location, the resolved location, then `vendor/ClawBio`, and
warns on stderr if none is found.

## 4. Bugs found in live runs and fixed

Each fix is minimal and has an offline regression test in
`skills/equity-lit-auditor/tests/test_integration_fixes.py` built from trimmed copies of the real responses.

1. **Curated sample sets were counted once per score, per GWAS Catalog accession and per performance
   record** (`equity_lit_pgs.py`, `equity_lit_extract.py`, `equity_lit_auditor.summarise_pgs`). The paper-level
   de-duplication keyed on a snippet that contains the PGS ID, so a GWAS reused by several scores was summed
   once per score; PGS000014 lists Scott 2017 twice (GCST004773/GCST004774, same 159,208 people, country list
   reordered); `performance/search` returns one record per metric, 12 of them on sampleset PSS001117 for
   PGS000014. Live effect: Scott 2017 (PMID 28566273) reported as **955,248** Europeans (6 x 159,208), now
   159,208; PGS000014's per-score table went from GWAS EUR 318,416 to 159,208 and evaluation EUR 1,765,094 to
   1,014,575; the T2D run
   total fell from 28,732,094 to 9,806,900 participant-analyses. Fix: a sample-set identity
   (paper, stage, ancestry, N) used everywhere, and evaluation links de-duplicated by sampleset ID.
2. **`score/search?trait_id=...&include_children=1` ignores `include_children`** (`equity_lit_pgs.gather`).
   Checked live: MONDO_0007254 returns 10 scores with or without it. "breast cancer" audited 10 scores from
   one publication (2025, Han Chinese population-specific PRS) and missed all 184 child-trait scores (breast carcinoma: PGS000001...). Fix: take
   `associated_pgs_ids` + `child_associated_pgs_ids` from the trait record, fetch by ID (lowest IDs first, up
   to `--pgs-max-scores`), and report how many were available. Now 194 available, 50 audited, 90 publications.
3. **Negated ancestry terms were read as the group they negate** (`equity_lit_extract.py`). `\bEuropean`
   matches inside "non-European" (the hyphen is a word boundary), and the Hispanic pattern ran before
   "non-Hispanic white". Live effect: Graham 2021 "The power of genetic diversity in GWAS of lipids"
   (PMID 34887591), "including 350,000 of non-European ancestries", came out as **350,000 Europeans** and was
   flagged "European-ancestry participants only"; "5,000 non-Hispanic white participants" came out as 5,000
   Hispanic. Fix: negated forms matched first ("non-Hispanic white" → EUR, "non-Hispanic Black" → AFR, any
   other "non-X" → OTH).
4. **Populations named as excluded were counted as participants** (same file). Exposed by fix 3 on the WTCCC
   2007 abstract (PMID 17554300): "provided individuals with non-European ancestry are excluded" became OTH
   participants (before fix 3 it was wrongly read as European). Fix: a mention followed by "were/are
   excluded/removed…" in the same clause, or preceded by "excluding/removed…", is dropped. Clause-bounded, so
   "After excluding related individuals, 5,000 Nigerian adults remained" is kept.
5. **Silent partial failures** (`equity_lit_auditor.main`). Europe PMC returns a persistent HTTP 500 for some
   open-access `fullTextXML` requests (5 of 6 PMCIDs probed, reproducibly); these and failed reference/citation
   lookups were printed to stdout only. They are now in `summary.retrieval_warnings` and a *Data availability*
   section of the report. PGS IDs the Catalog does not return, and performance lists longer than the 500 read,
   are also reported. Nothing is substituted for missing data.
6. **Trait matching fell back silently** to the first three search hits when no label contained the term.
   Now: exact label → exact synonym → label contains → first hits, and the report states which one matched.
7. **Stage figure mislabelled "Asian unspecified" (ASN) as "Multi-ancestry / other"** (`equity_lit_render.py`).
   T2D evaluation has 5,362 such participants. ASN now has its own slot.
8. **Space-grouped thousands were split** (`equity_lit_extract.NUMBER` / `parse_number`), found while attaching
   the breast-cancer literature context to PRSGuard results: "70 877 women" (JNCI/BMJ style) was read as 877
   and "53 051" as 51. Numbers grouped by spaces, thin spaces or no-break spaces are now one number.
   Regression test: `test_space_grouped_thousands_are_one_number`.
9. **Score names were read as sample sizes**: "the PGS 313 for American women" gave `total_n` = 313. Numbers that
   follow PGS/PRS/GRS or "risk score" are identifiers now. Regression test: `test_score_names_are_not_sample_sizes`.
   Known limitation that remains: the text-mined `total_n` is the largest single participant count mentioned
   (e.g. "260 breast cancer cases and 7845 [non-cases]" gives 260); curated PGS Catalog counts are preferred
   where available.

Known limitation, documented rather than changed: same-ancestry sample sets of one paper with different N
are summed (upstream design). Mahajan 2018 (PMID 30297969) reports 898,130 unadjusted and 574,306
BMI-adjusted Europeans, mostly the same people, shown as 1,472,436. Overlapping analyses cannot be told apart
from sex-stratified sets that should be summed.

## 5. Synthetic data can never pass as real

Where synthetic content can come from: only `--demo`, which loads `examples/demo_epmc_fixture.json` through
`FixtureClient` / `PGSFixtureClient` (15 invented Europe PMC records, 3 invented PGS scores; IDs use a `DEMO`
source and titles start with `[SYNTHETIC]`). That is the only place the fixture is loaded. There is no
fallback to it: if Europe PMC or the PGS Catalog cannot be reached the run exits 3, writes no report and says
so ("live results are never replaced by demo data").

Guarantees, each covered by a test in `test_integration_fixes.py`:

| Artifact | Machine-readable | Visible |
|---|---|---|
| `result.json` | top-level `synthetic: true`, `data_provenance: "SYNTHETIC DEMO"`; repeated in `summary`, `data`, `data.provenance`; `datasets` name the fixture | n/a |
| `report.md` | `**Data provenance**: SYNTHETIC DEMO` | H1 and every section heading end in `(SYNTHETIC DEMO)`; demo banner; closing line |
| every CSV (6 tables) | first column `data_provenance`, `SYNTHETIC DEMO` on every row | same |
| `population_heatmap.png`, `ancestry_representation.png`, `pgs_stage_ancestry.png` | PNG text chunks `data_provenance`, `synthetic=true`, `Title` | title suffix `(SYNTHETIC DEMO)` in red, e.g. "PGS Catalog: ancestry of participants at each stage (SYNTHETIC DEMO)", plus a "SYNTHETIC DEMO · NOT REAL LITERATURE" watermark |
| `population_map.html` | `data-provenance` / `data-synthetic` on `<html>`, meta tag, `DATA_PROVENANCE` JS const | `<title>`, red H1, alert banner, SVG watermark |
| stdout | n/a | the run header and summary lines start with `[SYNTHETIC DEMO]` |

Live outputs say `data_provenance: "LIVE"` with sources and retrieval time, and a test checks that no
`SYNTHETIC` label appears in them. With `--cache-dir`, the report notes that cached responses were replayed.

## 6. The equity score is context only

The per-paper 0-100 rubric grades how a paper reports and samples populations. It is not evidence about
whether a polygenic score is valid, calibrated or transferable for a person. In PRSGuard it must never feed
an applicability decision: not the `prs-gate`, not a threshold, weight or tie-breaker. It may be shown next
to a gate result as clearly labelled literature context.

- `result.json`: `data.equity_score_semantics = {role: "context_only", feeds_applicability_decision: false, ...}`
  and `summary.equity_score_role = "context_only"`. The score itself is kept.
- `papers.csv`: an `equity_score_role` column; `report.md`: the rule is stated above the score table.
- `SKILL.md`: Agent Boundary, Integration (`prs-gate` chaining) and Gotchas say the same.
